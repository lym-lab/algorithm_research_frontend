# 算法提交指南

本指南适用于希望将方法加入共享目录的算法贡献者。接口字段与文件格式见[算法接入规范](算法接入规范.md)。

## 1. 准备接口和样例

准备能够接收素材与参数、返回处理结果的 HTTP 接口，以及至少一组有对应关系的输入、实际输出和效果说明。确认接口可从使用者浏览器访问。

## 2. 创建方法配置

在平台的“接入算法”页面填写方法信息、接口、素材输入、额外参数与样例。可导入已有 JSON，也可参考 [视频防御模板](../public/templates/video_defense.json)。

每个额外参数单独添加一项，填清名称、类型、默认值、范围和说明。没有额外参数时，保留空参数列表。

点击“登记到本机预览”可在当前浏览器的方法集合中测试。该登记保存在本机浏览器；共享时需继续完成下方的文件提交。修改已登记配置前，可先在方法详情移除旧的本机登记，再重新登记。

点击“导出配置”下载 `方法ID.json`。可在 JSON 中补充参数步长、文字长度、样例参数和更多样例。

## 3. 放置共享文件

在个人 Fork 或工作分支中增加以下文件：

```text
public/
├── methods/
│   ├── index.json
│   └── my_video_defense.json
└── samples/
    └── my_video_defense/
        ├── input.mp4
        └── output.mp4
```

在 `public/methods/index.json` 数组末尾追加配置文件名，保留已有条目。例如：

```json
[
  "image_watermark.json",
  "audio_marker.json",
  "my_video_defense.json"
]
```

配置里的样例路径填写 `samples/my_video_defense/input.mp4` 等相对路径。样例使用公开 URL 时，可不提交对应素材文件，但应确保地址稳定可访问。

## 4. 本地验证

在仓库根目录执行：

```bash
npm install
npm run dev
```

打开方法集合，确认方法、样例、参数与真实接口可正常使用。完成[接入自查清单](接入自查清单.md)，再执行：

```bash
npm test
npm run build
```

## 5. 提交 Pull Request

向 [algorithm_research_frontend](https://github.com/lym-lab/algorithm_research_frontend) 的 `main` 分支提交 Pull Request，说明：

- 方法名称、ID、用途与论文来源。
- 支持的素材、额外参数和输出类型。
- 已验证的运行环境，以及接口可用性或使用限制。
- 样例的输入输出对应关系、参数和观察重点。
- 自查与测试结果。

合并后，其他使用者更新代码即可在共享目录中看到方法：

```bash
git pull
```

更新已有方法时保留原 ID，调整版本号、说明和相关样例。移除方法时删除索引条目、对应配置和不再使用的专属样例文件；算法服务中的文件由服务提供者管理。
