# 算法提交指南

小组成果采用 **Fork → 在本组仓库完成接入 → 重写根目录 README → 发起 PR → 在同一 PR 中持续更新** 的方式提交。公共仓库集中查看与反馈小组成果，成果 PR 保持打开，默认不合并。

## 1. Fork 基础仓库

打开 [algorithm_research_frontend](https://github.com/lym-lab/algorithm_research_frontend)，点击 **Fork**，在本组负责人账号下创建副本。每组使用一个仓库，组员可在该仓库协作。

请使用 Fork 保留与公共仓库的关系，方便回提 PR。GitHub 的“Use this template”会创建独立历史的仓库，与 Fork 不同，详见 [GitHub 官方说明](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-repository-from-a-template)。

克隆本组 Fork，而非直接在公共仓库中开发。例如：

```bash
git clone https://github.com/YOUR_ACCOUNT/algorithm_research_frontend.git
cd algorithm_research_frontend
git switch -c group_12_submission
```

将账号、仓库名和组号换为实际值。推荐方法 ID 带组号，例如 `group_12_audio_watermark`；它与配置中的 `id`、样例目录和 README 中记录保持一致。

## 2. 在本组仓库接入方法

按[算法接入规范](算法接入规范.md)准备 HTTP 接口、方法 JSON 和至少一组真实输入输出样例。在“接入算法”页面填写或导入配置，设置素材输入及每个额外参数，导出配置。

“登记到本机预览”只保存在当前浏览器，用于测试。它不会把文件提交到 GitHub，也不会自动加入公共目录。

在本组仓库放置文件，并在索引中追加配置文件名，保留已有条目：

```text
README.md                           本组成果说明
public/methods/group_12_audio_watermark.json
public/methods/index.json            追加方法配置文件名
public/samples/group_12_audio_watermark/  输入与输出样例
algorithms/group_12_audio_watermark/  推荐的算法代码与环境文件位置
```

算法代码也可保留在独立源码仓库，但必须在本组 README 给出可访问的仓库和明确的版本或提交链接。样例相对路径使用 `samples/方法ID/文件名`，不带 `public/` 前缀；使用公开 URL 时应确保稳定可访问。

## 3. 重写根目录 README

将[小组 README 模板](小组README模板.md)复制到本组提交分支根目录的 `README.md`，填写实际内容并删除占位提示。

根目录 README 是成果查看的主入口，至少包括：

- 组号、选题、成员和分工。
- 论文与 baseline 来源、本组实现内容与改动。
- 输入、输出及每个额外参数的含义。
- 环境、安装、服务启动、前端运行和第一次处理的具体步骤。
- 输入输出样例、复现参数、验证结果及已知限制。
- 所有附加文档、算法代码、配置和样例的可点击入口。

可以增加详细实验记录、环境文档等，但必须从根目录 README 链接进入。不能直接沿用平台 README 或 baseline README，不能把唯一的成果说明藏在子目录、改名后不给入口。第三方项目的来源与许可证应保留。

## 4. 本地检查并推送

按本组 README 启动算法服务，在仓库根目录运行：

```bash
npm install
npm run dev
```

确认样例、素材上传、参数传递、实际结果预览和下载正常，再完成[接入自查清单](接入自查清单.md)，执行：

```bash
npm test
npm run build
```

检查提交文件列表后，将本组改动提交并推送到同一分支：

```bash
git add README.md public/methods public/samples
git commit -m "Add group 12 method and documentation"
git push -u origin group_12_submission
```

若另有算法代码、环境文件和附加文档，也需明确加入提交。避免提交模型权重、环境压缩包、用户任务数据和服务凭据。

## 5. 发起一个成果 PR

在本组 Fork 中选择 **Contribute → Open pull request**，确认：

- 目标仓库：`lym-lab/algorithm_research_frontend`。
- 目标分支：`main`。
- 来源：本组 Fork 的实际提交分支，例如 `group_12_submission`。

标题统一为 **`第XX组-选题名称`**，XX 替换为实际组号：

```text
第12组-面向语音的鲁棒水印
第103组-视频主动防御
```

避免使用“完成作业”“更新代码”“final”等无法识别组别和选题的标题。正文按自动出现的 PR 模板填写，尤其要提供**本组提交分支根目录 README 的完整 GitHub 链接**，例如：

```text
https://github.com/YOUR_ACCOUNT/algorithm_research_frontend/blob/group_12_submission/README.md
```

PR 中列明方法 ID、源码与样例位置、已验证环境、接口状态和限制。每组提交一个成果 PR；多个方法在同一 PR 和 README 中列出。

## 6. 后续修改与成果查看

收到反馈后修改同一提交分支并继续推送，原 PR 会更新，无需反复新建 PR。保留该分支与 Fork 仓库，以便持续查看；不要自行关闭或合并成果 PR。

未合并 PR 中的方法可在本组 Fork 中运行，但不会自动出现在公共平台目录。维护者通过 PR 集中查看成果；需要正式收录的方法，会另行整理其配置、索引和样例，保留公共平台的 README 与共享组件。

PR 模板提供填写提示，标题和 README 要求仍需各组自行遵守并由维护者检查。
