# 算法接入规范 V1

## 1. 输入范围

每方法声明 1–8 个独立素材字段。支持图像 `image`、音频 `audio`、视频 `video`，可以组合，例如“一段音频 + 一张人像”。每字段声明 `name`、`label`、`kind`、允许 MIME 列表 `accept`、`required` 与 `max_mb`（最大 500 MB，实际服务可设得更小）。

额外文本、种子、密钥文本（非服务访问密钥）、强度、选项等放在 `parameters`。支持 `text`、`textarea`、`number`、`integer`、`select`、`boolean`，可声明 `default`、`required`、`help`、`min`、`max`、`step`、`max_length`。字段名在一个方法内不能重复。

前端验证只是便利；算法端必须再次校验格式、大小、解码、参数范围与资源需求。不得把浏览器上传的文件名直接拼成执行命令。

## 2. 请求

`adapter: { "type": "http", "endpoint": "https://your_algorithm.example/process" }`

前端 POST multipart/form-data：

| 字段 | 类型 | 内容 |
| --- | --- | --- |
| `inputs[].name` 的实际名称 | 文件 | 可有多个，保留上传文件名 |
| `method_id` | 字符串 | 方法 ID |
| `parameters` | JSON 字符串 | 例如 `{"strength":0.05,"seed":42,"repeat":false}` |

前端不手动设置 multipart 的 Content-Type，让浏览器生成 boundary。无 cookie 或服务密钥自动注入。公开配置不应存秘密。服务若需要身份验证，应通过后续受控后端扩展，不能把密钥写进 GitHub。

此版本等待同一 HTTP 请求完成。长任务应在服务端设置适合的超时或未来增加 job 提交 / 查询 / 取消契约。平台当前没有全局 CPU / GPU 调度器。

## 3. 响应

HTTP 200 + application/json：

```json
{
  "message": "防御处理完成",
  "artifacts": [
    {
      "kind": "video",
      "label": "保护后视频",
      "filename": "protected.mp4",
      "url": "https://your_algorithm.example/files/protected.mp4"
    },
    {
      "kind": "json",
      "label": "水印溯源报告",
      "filename": "report.json",
      "url": "https://your_algorithm.example/files/report.json"
    }
  ]
}
```

支持 1–20 个结果：`image` / `audio` / `video` / `json` / `text`。前三类预览播放，后两类显示文件入口与下载。可以只返回溯源报告，不强制返回媒体。URL 必须 HTTP(S)，相对地址按接口 URL 解析；不能返回服务器磁盘路径或内联脚本。

失败返回合适 HTTP 状态码与 `{"error":"面向用户的说明"}`。禁止伪造随机概率或把样例文件作为任意用户输入的结果。

## 4. 样例

`examples` 至少一个元素，包括：

- `title`、`description`：样例与目标效果解释。
- `input: {src, kind, label}`、`output: {src, kind, label}`：可访问文件，相对 `src` 从前端根目录解析，例如 `samples/my_method/input.mp4`。
- `parameters`：建议补充产生该样例的参数，单素材方法可一键试跑；多素材方法目前需手动上传各输入。

样例展示支持图像、音频、视频；如果方法只输出溯源报告，提供一张真实报告截图作为效果样例，实际任务依然可返回 JSON / 文本文件。

只提交获准公开的数据。建议每组样例合计小于 20 MB，视频控制为短片段。无需提交模型权重、Conda 环境、训练数据或用户任务文件。

## 5. 一二百种方法如何统一

每组维护一个 JSON，索引只保存文件名。所有方法共享动态表单、媒体预览、运行工作区和结果组件。路由为 `#/methods/方法ID`，ID 全局唯一。增加算法通常不改 React 页面；新增输入组件或异步协议才需扩展前端。

各算法环境独立运行，不向前端或同一 Python 环境安装各组依赖。可以保留各自的 Conda / venv / 容器方案，不要求前端分发大型镜像。运行配额、依赖安装和调度属于算法侧。HTTP 接口、方法 JSON 与公开样例才是本仓库的接入边界。

## 6. 接入文件与检查

参考 `public/templates/video_defense.json`，可在接入页导入修改。完成后放到 `public/methods/`，更新索引，放入样例并提交 Pull Request。

测试：有效 / 缺失素材、所有参数类型与边界、服务不可用、结果预览和下载、方法详情刷新、不同尺寸页面。`npm test` 和 `npm run build` 应通过。
